# 第一章 技术栈

| 项目 | 选型 |
|---|---|
| 引擎 | Godot 4.6.2（mono 版安装包，但本项目**纯 GDScript，不使用 C#**） |
| 脚本语言 | GDScript 4.x |
| 测试框架 | GUT 9.7.1（vendored 于 `addons/gut/`，随仓库一起提交） |
| 渲染后端 | `gl_compatibility` —— 2D 卡牌游戏够用、兼容性最好、启动快 |
| 版本控制 | Git（SSH 推送） |
| 数据格式 | 数值与内容一律 `.tres`，代码只读不算 |

## 1.1 一条全局硬约束

`gdscript/warnings/enable_all_warnings=true`，且**警告会导致脚本解析失败**。

> 最常见的踩坑：`var x := <Variant 值>` 会触发「类型从 Variant 推断」警告。
> 写法上显式标注 `var x: Variant = ...` 即可绕开。

## 1.2 验收方式

全部验收走 `tools/ci_check.sh`（六步门禁），不依赖图形编辑器：

1. 脚本解析检查
2. 目录结构完整性
3. 场景冒烟测试（全量编译 + 挂树）
4. GUT 单元测试 + 用例数对账
5. 分层铁律（`scripts/ui/` 不得依赖 `battle/` 或 `pipeline/`）
6. 内容引用完整性

## 2.2 三大 Autoload 契约（§10.5 纪律）

| Autoload | 职责 | **禁止** |
|---|---|---|
| `GameState` | 跨场景全局状态：`character_class` / `job_path` / `divinity` / `humanity` / `relics` / `advance_job()` | ❌ 放战斗逻辑 |
| `EventBus` | 跨场景信号总线（**只放真正跨场景的事件**） | ❌ 放场景内事件 |
| `ContentRegistry` | 卡牌/遗物/敌人/职业的**统一只读查询入口** | ❌ 放可变状态 |

> **原则**：Autoload 是服务定位器，不是游戏逻辑的垃圾场。任何能放进实例化场景的逻辑都不该进 Autoload。

## 2.3 分层铁律（不可违反）

1. **`scripts/ui/` 下任何文件不得 `import`（`preload`/`load`/类型引用）`battle/` 或 `pipeline/` 的逻辑**——只能**发信号**和**读只读状态**。
2. **数据外置**（§10.6）：卡牌费用/伤害/格挡、敌人血量/攻击、奖励权重、神性来源数值、遗物数值——**一律 `.tres`**，代码只读不算。
3. **管线顺序一旦定下写进测试，永不随意改动**——改这里等于改全部 12 个终职。
4. **身份层不可剥夺由架构保证**，不靠"记得写判断"。

## 2.4 GDScript 编码规范（Godot 4.x）

```gdscript
# 显式类型标注（强制）
var health: int = 100
var enemies: Array[Enemy] = []
func take_damage(amount: int, _source: Node = null) -> void:   # 未用参数加 _

# 类型推断陷阱：for 迭代变量与字典取值必须显式标注
for x: float in [-1.0, 1.0]:
    pass
var value: int = data["a"]        # 不能写 var value := data["a"]

# 命名：类 PascalCase / 变量 snake_case / 私有 _snake_case / 常量 UPPER_SNAKE / 信号 snake_case
# 缩进：Tab
```

**生成代码前必过的自检清单**（避免编辑器红黄警告刷屏）：

- [ ] 局部变量名**不得**与内置函数重名：`hash` `len` `str` `int` `float` `bool` `print` `abs` `min` `max` `clamp` `lerp` `sign` `range` `load` `preload`
- [ ] `extends Node3D/Node2D` 时，局部变量**不得**用：`transform` `basis` `position` `rotation` `scale`
- [ ] `extends Control/CanvasItem` 时**不得**用：`visible` `modulate` `material`
- [ ] 所有函数参数都有用；接口参数加 `_` 前缀
- [ ] `int / int` 表达式：显式 `@warning_ignore("integer_division")` 或改 float
- [ ] 每个声明的 `signal` 都真的会 `emit()`
- [ ] `@warning_ignore` 只用于「故意如此 / 接口约束 / 待办占位」，不用来压没搞懂的警告

## 2.5 资源文件规范（§12.6）

- `.tscn` / `.tres` **不手写 UID**，交给引擎生成
- `.tscn` 中**不写注释**（Godot 解析器不支持）
- `.tscn` 以 `[gd_scene load_steps=N format=3]` 开头；`.tres` 以 `[gd_resource type="..." format=3]` 开头
- **优先在 Godot 编辑器内创建** Resource / Scene，代码只在必要时生成

## 2.6 验证命令（headless，每次提交前跑）

```bash
GODOT="***REMOVED***/Godot_v4.6.2-stable_mono_win64/Godot_v4.6.2-stable_mono_win64/Godot_v4.6.2-stable_mono_win64_console.exe"

# ① 脚本解析检查（改了 .gd 就跑）

# ④ 缓存修复（编辑器报"引用了不存在的资源"但文件明明在）
```

> ⚠️ 不要删整个 `.godot/`（会连 `shader_cache/` 一起清掉，下次开编辑器要重建很久）。

## 2.7 Git 工作流（§12.1 / §12.3）

**分支**：`main`（永远可运行）/ `feature/xxx` / `fix/xxx` / `refactor/xxx` / `test/xxx` / `content/xxx`

**提交信息按"系统"组织，写清"为什么"与"防御了什么失效模式"**：

```
feat(identity): 增加不可剥夺身份层与 JobData 注入
feat(pipeline): 将身份能力并入伤害修正链
feat(job): 增加壁垒回合末格挡留存规则钩子
fix(deck): 抽牌堆空时禁止在结算中途触发洗牌
test(identity): 验证 remove_power 对身份层无效
content(cards): 增加盾卫 6 张职业牌初值
```

**任务卡粒度硬性规则**：
> **一张任务卡 = 一次 commit = 一个可独立测试的行为。**
> 判定法：如果一张卡需要用"和"连接两件事 → 拆成两张。

**每次改动的必测项（§12.5）**：开局抽牌 / 出牌扣能量 / 回合结束弃牌 / 敌人回合结算 / 空堆洗牌 / 死亡结束战斗。

# 第三章 架构蓝图：两个心脏

> 设计文档 §15.1 决策 12：**伤害管线 + 身份层先建、先测、最后改**。本章给出这两个模块的**精确契约**——写代码前先把接口钉死。

## 3.1 心脏 1：伤害管线 `DamagePipeline`

### 修正链顺序（**固定，写进测试**）

```
① 基础值 base
② [攻击方] 遗物 at_damage_modify            ← 最先介入，会被后续乘法放大
③ [攻击方] Power.at_damage_give             ← 力量（加法）
④ [攻击方] Power.at_damage_give (priority=99) ← 虚弱（×0.75，高优先级保证在加法之后）
⑤ [攻击方] Stance.at_damage_give            ← 姿态（兽形 ×1.5 / 人形 ×1.0）
⑥ [防御方] Power.at_damage_receive          ← 易伤 ×1.5 / 印记 / 奥术
⑦ [攻击方] at_damage_final_give             ← 二次修正
⑧ [防御方] at_damage_final_receive          ← 二次修正
⑨ floor() 一次 + max(0, result)             ← 只取整一次、保证非负
⑩ 格挡吸收 → 扣血
```

### 关键实现约束

| 约束 | 说明 |
|---|---|
| **加法先于乘法** | 力量（加）必须先于虚弱（乘）。用 `priority` 字段控制，虚弱设 `priority = 99` |
| **取整只做一次** | 中间全用 `float`，**只在最终结果 `floor` 一次** |
| **非负保证** | 修正后可能为负，必须 `max(0, result)` |
| **DamageType 分流** | `NORMAL` 吃全部修正；`THORNS`（荆棘）跳过力量/虚弱/易伤；`HP_LOSS`（生命流失）跳过几乎所有修正。**Power 钩子内必须先检查 `type == NORMAL` 再修正**，否则荆棘/中毒会被力量加成 |
| **身份层合并** | `_sorted_powers_of()` 必须**合并** `powers + identity_powers`——身份能力同样要进修正链 |
| **盾猛接线** | 盾猛 = "每次 `gain_block` 触发一次对敌伤害"，伤害类型 `NORMAL`（吃力量/易伤）。3 张各 5 格挡的牌 = 触发 3 次 |

### 对应数据类

```
DamageType  枚举：NORMAL / THORNS / HP_LOSS / POISON / SHIELD_BASH(废弃保留)
DamageInfo  封装：owner / target / type / base / output / is_modified
```

## 3.2 心脏 2：身份层 `IdentityLayer`（不可剥夺）

**"不可剥夺"必须由架构保证，而不是靠记得写判断。**

```gdscript
# AbstractPower
var is_identity: bool = false          # 身份能力标记
var is_turn_based: bool = false        # 身份能力恒为 false

# Creature
var powers: Array[AbstractPower] = []           # 常规 buff/debuff
var identity_powers: Array[AbstractPower] = []  # 身份层（独立数组）
func apply_identity_power(power: AbstractPower) -> void
```

### 三条隔离规则（**每条都要有测试**）

| 规则 | 行为 |
|---|---|
| `remove_power()` | 对身份层**无效**（沉默 / 驱散 / 夺能接触不到） |
| `on_turn_end()` | **不对**身份能力倒计时 |
| 战斗 `reset()` | **不清**身份层——身份能力的"源头"挂在 `GameState` 的 `JobData` 上，每场战斗初始化玩家 `Creature` 时**重新实例化注入** |

> **为什么这样设计**：任何战斗内效果都接触不到 `GameState.JobData`，所以"不可剥夺"是物理性的，不是规则性的。叙事上的"刻入灵魂"由代码结构直接映射。

### 6 个规则级钩子（`AbstractPower` 统一接口）

```
on_turn_start(creature)          on_turn_end(creature)
at_damage_give(dmg, type, card)  at_damage_receive(dmg, type, card)
on_card_played(card)             on_kill(target)
```

> 钩子**默认返回原值**，子类只 override 关心的那个。这是"12 个终职挂在同一条链上"的实现基础。

## 3.3 全项目统一钩子清单（阶段 2 一次建全）

```
Creature : on_turn_start / on_turn_end / at_damage_receive / at_damage_modify
           on_kill / on_battle_start / on_battle_end / on_health_lost / on_block_gained
Power    : on_turn_start / on_turn_end / at_damage_give / at_damage_receive
           on_card_played / on_kill
Relic    : at_damage_modify / on_use_card / at_battle_start / on_turn_start / on_turn_end
```

> 阶段 2 把钩子**一次性建全**（哪怕暂时没人用），阶段 4~6 的内容只需"挂上去"。这是"先建先测最后改"的具体含义。

## 6.2 必须建立的三个调优指标（§14.2）

| 指标 | 定义 | 健康区间 |

## 6.3 每轮 playtest 记录项（§14.3）

- 平均战斗回合数（分普通 / 精英 / Boss）

- 哪张卡明显过强
- 哪种开局最容易滚雪球
